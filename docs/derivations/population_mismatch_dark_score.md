# The dark-class score bias from population misspecification — derivation memo

**Date:** 2026-08-20 · **Status:** derivation + quantitative post-hoc confirmation; the
PRE-REGISTERED confirmation (B-OUT, job 6385173) is in flight. Authored under the author's
autonomy grant; the fork in §6 returns as a [RULE]. **No production change proposed here.**

**Object:** the production base tilt — the 1D posterior railed at 0.601 (2D −0.053 after the
B_scale removal), shown in `PREREG_COMPLETION_CLASS_DECOMPOSITION.md` to be carried by the
pure-completion (dark) class with a per-event score at truth of **−0.635 ± 0.017** (37σ).

## 1. The identity being violated

For data generated by the model itself, the score has zero mean at truth:
E_true[∂_h ln p(d|h)]|_{h_true} = ∂_h ∫ p(d|h) dd = ∂_h 1 = 0. A large non-zero mean score
therefore means the data are NOT drawn from the estimator's model. For dark events the
estimator's model is

    p(d_obs|h) ∝ (1/D̃^φ(h)) ∫ dz  w_model(z;h) (1−f(z)) S(z;h) p_gw(d_obs | d_L(z;h))

with **w_model = constant comoving number density × dV_c/dz/(1+z)** — an explicit modelling
assumption (`bayesian_statistics.py:1192`, used at :1590/:1666). The events, however, are
injected from the **Barausse (2012) M1 EMRI rate** (arXiv:1201.5888), whose redshift shape
w_true(z) differs.

## 2. First-order prediction of the induced score bias

σ_dL/d_L ≈ 10⁻³–10⁻¹, so the z-integral is dominated by the saddle z*(h) with
a(z*) = h·d_obs (a ≡ h·d_L). Writing the slowly varying factors as
g(z) = w(z)(1−f(z))S(z)·|dz/dd_L|, ln p ≈ ln g(z*(h)) − ln D̃^φ(h), so the score difference
between analysing with w_model and with the true w_true is

    **Δscore(z) ≈ [ d ln(w_model/w_true)/dz ]_(z) × (dz*/dh),   dz*/dh = a(z*)/(h · da/dz)**

— the log-slope of the population ratio times the redshift lever arm. Only the ratio's
SHAPE enters (normalisation cancels), which is why a self-consistent harness sees nothing.

this order: the derivation drops the z-dependence of (1−f)S relative to the population term,
uses a saddle-point approximation, and takes w_true from a finite pool histogram.

## 4. Why four campaigns of elimination could not see this

The validation harnesses (`pp_coverage`, `calibration_gate`, `venue_transfer`) **generate
events from the same population they analyse**, so w_model ≡ w_true by construction and
Δscore ≡ 0: a self-consistent harness is STRUCTURALLY BLIND to a data-vs-model population
mismatch, no matter how many arms it runs. This is the same blindness class as the
un-derived B_scale surviving every counterfactual that held it fixed (rows #130–#131).

## 5. Consequence for the systematics budget (returns to the author)

`docs/gates/G7_systematics_budget.md` **row 16** records the M1 population-shape choice as
affecting "rates/shape, **not estimator calibration** (P–P closes at injected truth)". The

parenthetical is exactly the §4 blindness — P–P closes because the harness is
self-consistent. Row 16 should be re-graded from QUOTED-forecast-assumption to a measured,
dominant, calibration-affecting systematic.

## 6. Fork (author [RULE]; none pre-decided)

- **(a) Self-consistent mock:** give the estimator the injected M1 dN/dz as its dark-class
  population prior. Removes the mismatch by construction; makes the mock a clean closure
  test but assumes the population is known — which a real analysis cannot.
- **(b) Hierarchical marginalisation (principled, matches the literature):** marginalise
  over population/rate-evolution parameters, so H₀ is not conditioned on an assumed rate
  shape. Largest scope; the honest form for a real dark-siren analysis.
- **(c) Document as the dominant systematic:** keep the comoving prior, quote the measured
  score/H₀ sensitivity and the z-resolved decomposition as the systematic's size.
- Any of these is a *modelling* decision, not a bug fix: the estimator's mathematics is not
  defective here — it is being conditioned on a population that is not the one that
  generated the data. Consistent with the binding value (correctness over bias-removal).
