<objective>
Port the settled static HORIZON design (Phases 1-5) to the Plotly interactive web
layer. All 8 Plotly factories share ONE `go.layout.Template` built from the SAME
`_colors` hex tokens used by the static figures (single source of truth), the
GH-Pages output becomes self-contained/archival-robust (no CDN), the two
dropdown/slider figures switch to a robust per-group trace model instead of
hand-maintained boolean visibility vectors, and the talk/web theme is wired into
generation with each interactive verified against its static PDF twin.

Purpose: The interactive set deploys to GitHub Pages under `interactive/`. Today it
hardcodes hex in `interactive.py`, uses `Viridis`/default Plotly colors that drift
from the static HORIZON palette, ships `include_plotlyjs="cdn"` (online-only,
fragile for archival), and the dropdown/slider figures
(`interactive_m_z_improvement`, `interactive_single_event_detail`) carry brittle
full-figure boolean visibility arrays that silently break when a trace is added.

Output: `_plotly_theme.py` (new), an overhauled `interactive.py` (8 factories +
`generate_all_interactive`), and extended `test_interactive.py`. No new dependency
(plotly 6.6 already present). No physics — pure presentation/web-layer work; never
`/physics-change`.

The 8 interactive -> static PDF twin mapping (all twins exist; none missing):

| # | Interactive factory | Static twin |
|---|---------------------|-------------|
| 1 | `interactive_combined_posterior` | `bayesian_plots.plot_combined_posterior` |
| 2 | `interactive_sky_map` | `sky_plots.plot_sky_localization_mollweide` |
| 3 | `interactive_fisher_ellipses` | `fisher_plots.plot_fisher_ellipses` |
| 4 | `interactive_h0_convergence` | `convergence_plots.plot_h0_convergence` |

| 6 | `interactive_single_event_detail` | `single_event_detail.plot_single_event_detail` |
| 7 | `interactive_closure_test_overlay` | `paper_figures.plot_closure_test_overlay` |
| 8 | `interactive_catalog_completeness` | `catalog_plots.plot_event_catalog_coverage` |

include_plotlyjs strategy CHOSEN: `'directory'` — Plotly writes a single
`plotly.min.js` once into the output dir (next to every HTML), so the whole
`interactive/` folder is self-contained at site level, works offline, and is
archival-robust. Rejected `'cdn'` (online-only/fragile) and full-inline
(`True`) (every HTML re-embeds ~3 MB of JS — site bloat across 8 files).
