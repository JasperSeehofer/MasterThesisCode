Chapter 0 — One coin, one posterior, one real event set

Before the full 14-parameter EMRI pipeline: what does “the posterior sharpens as evidence accumulates” actually look like, using data this project really produced?

Why this chapter exists Every later chapter builds a more detailed representation of one quantity: the posterior over the Hubble constant, $H_0$ (we work in the dimensionless $h = H_0 / 100\ \mathrm{km\,s^{-1}\,Mpc^{-1}}$). Before adding galaxy catalogs, completeness corrections, or Fisher matrices, we need the one idea everything else refines: Bayes’ rule, applied repeatedly as new events arrive.

1. Bayes’ rule, stated once

For a hypothesis $h$ (here: a value of the Hubble parameter) and data $D_i$ from one detected event $i$:

$$ p(h \mid D_i) \;=\; \frac{ \mathcal{L}_i(D_i \mid h)\, \pi(h) }{ p(D_i) } \;\propto\; \mathcal{L}_i(h)\, \pi(h). $$

With a flat prior $\pi(h)$, the posterior from a single event is just its likelihood $\mathcal{L}_i(h)$, renormalized. The question this chapter's widget answers experimentally: what happens when you multiply many of these together?

2. Combining events: a product of likelihoods

For $N$ independent events, conditioning correctly on “these $N$ were detected” (Loredo 2004; Mandel, Farr & Gair 2019, arXiv:1809.02063 §3) gives simply a product of per-event likelihoods — computed in log-space for numerical stability:

$$ p(h \mid D_1, \dots, D_N) \;\propto\; \prod_{i=1}^{N} \mathcal{L}_i(h) \quad\Longleftrightarrow\quad \log p(h \mid D_{1:N}) \;=\; \sum_{i=1}^{N} \log \mathcal{L}_i(h) \;+\; \text{const.} $$

This is exactly combine_log_space() in master_thesis_code/bayesian_inference/posterior_combination.py — the book cites it, it does not re-derive it.

Both are half right. At small $N$ (1–10 events) the MAP can land almost anywhere on the grid — try $N=2$ or $N=5$ and watch it jump to the grid edge. That is real Poisson/measurement noise, not a bug. Only once enough events accumulate does the product-of-likelihoods concentrate near the true value. This is precisely why a single dark-siren event can never measure $H_0$ on its own — the whole point of the pipeline in later chapters is to make each $\mathcal{L}_i(h)$ as informative and unbiased as possible before stacking.

3. Self-check

Q1. Why is the combination done as a sum of log-likelihoods rather than a product of raw likelihoods?

Show answer
Numerical underflow. With ~1500 events multiplied directly, the product underflows double-precision floats almost immediately. Working in log-space and subtracting the running maximum before exponentiating (the same "log-sum-exp" trick used throughout the codebase) keeps every intermediate value representable.

Q2. In the widget, why does the MAP estimate sometimes move away from 0.73 when you increase $N$ from, say, 50 to 100?

Show answer
The subsets are nested along one fixed random draw order (seed 42): going from $N=50$ to $N=100$ adds 50 new events whose likelihoods are not centered on 0.73 either — real host galaxies, noise realizations, and (as later chapters show) a genuine unresolved 2D-channel bias all contribute. Convergence to the truth is a large-$N$ statistical statement, not a guarantee that every intermediate $N$ improves monotonically.
